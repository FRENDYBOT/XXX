# fop_info

Невелика програма на Python 3.12, яка підключається до фіскального сервера ДПС і читає дані про ФОП. Лише читання: вона не створює чеків, не відкриває й не закриває зміни.

Стан: готовий етап 1 (зв'язок без підпису). Підпис КЕП (етап 2) і команди Objects, Operators, TransactionsRegistrarState, Shifts, ZRep (етапи 3–5) ще не написані.

## Встановлення

Залежностей немає, потрібен лише Python 3.12.

## Конфіг

Скопіюйте `config.example.toml` у `config.toml` **поза репозиторієм** і вкажіть шлях через `--config` або змінну `FOP_INFO_CONFIG`. Без конфігу програма працює зі стандартними адресами ДПС.

Ключ КЕП і пароль у репозиторій не потрапляють: шлях до ключа лежить у конфігу поза репозиторієм, пароль запитується при запуску або береться зі змінної `FOP_INFO_KEY_PASSWORD` (етап 2). `.gitignore` закриває типові файли ключів і вивантажені дані.

## Запуск

```
python fop_info.py --server-state
```

Виводить адресу, що відповіла, час сервера і різницю з годинником ПК. Якщо перша адреса недоступна, пробує другу й показує, що вона без шифрування.

## Тести

Без ДПС, на локальному HTTP-сервері:

```
python -m unittest discover -s tests -t .
```

Тести перевіряють логіку програми, а не відповідність формату запиту вимогам ДПС.

## Правила безпеки в коді

- Білий список команд (`dps/whitelist.py`): ServerState, Objects, Operators, TransactionsRegistrarState, Shifts, ZRep. Усе інше, включно з DeviceRegister і шляхом `/doc`, відхиляється до відправки.
- Не більше 2 запитів на секунду (`dps/throttle.py`); у конфігу більшого значення програма не прийме.

## Типові помилки

| Повідомлення | Що робити |
| --- | --- |
| Жодна адреса сервера ДПС не відповіла | Перевірте інтернет, VPN, брандмауер; у тексті помилки видно причину по кожній адресі |
| немає відповіді за N с | Сервер повільний або недоступний; збільште `timeout_seconds` |
| Не авторизовано (401) | Сервер не прийняв підпис або ключ |
| Доступ заборонено (403) | Ключ не має прав на цей ПРРО чи дію |
| Не знайдено (404) | Перевірте адресу сервера й номер ПРРО |
| Даних немає (204) | Сервер відповів успішно, але нічого не повернув |

## Що ще треба перевірити за описом API

У `dps/client.py` дві константи, взяті не з офіційного опису: `COMMAND_KEY` (ключ з назвою команди в JSON) і `TIMESTAMP_KEY` (поле з часом у відповіді ServerState). Їх треба звірити з описом і виправити, якщо відрізняються.
